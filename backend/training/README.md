# Fine-tune Laya to categorise Indian bank transactions: a step-by-step guide

This guide shows how to teach **Laya**, a small open-source decision model, to put Indian bank
narrations like `UPI/412345678/SWIGGY/swiggy@icici` into categories like *Food & Dining*. You train
on a **free Kaggle GPU** using **synthetic data only**, then run the model **on your own computer**.
Your real transactions never leave your machine.

Why we did it this way: see the [case study](../../docs/case-study-laya-fine-tuning.md).

```text
 generate synthetic data ─▶ check it ─▶ train on Kaggle (GPU) ─▶ download checkpoint
        (your PC)          (your PC)        (free, ~1 hour)           (your PC)
                                                                          │
      use it in the app ◀── decide ◀── evaluate on your real data ◀── run locally in Docker
```

## What you need

| | Why |
|---|---|
| A [Kaggle](https://www.kaggle.com) account, **phone-verified** | Verification unlocks free GPUs and internet in notebooks |
| [uv](https://docs.astral.sh/uv/) and this repository | To generate the data and run the evaluation |
| Docker Desktop, about 4 GB free memory | To run the trained model locally |

## Key ideas (read once)

- **Fine-tuning** means continuing to train an existing model on examples from your own task, so it
  learns your vocabulary. Here it learns that SWIGGY means *Food & Dining*.
- **A labelled example** is one input plus its correct answer. Each training row holds a narration,
  whether money went out or came in, an amount, and the correct category.
- **Synthetic data** is made-up examples generated by code: real brand names, random reference
  numbers, and random person names. It contains no personal data, so you can upload it anywhere.
- **An evaluation set** is examples kept out of training, so you can measure accuracy honestly.
  The real test is **your own transactions**, labelled by you, and those stay on your PC.

## Step 1: Generate the training data

From the `backend/` folder:

```bash
uv run python training/generate_dataset.py
```

The output is `training/data/round-1/train.jsonl` (4,320 rows) and `eval.jsonl` (480 rows): 150
examples for each of the 32 categories. The command prints three samples per category. **Read
them.** If a narration looks wrong for its category, fix the templates in `generate_dataset.py`
before you train.

Each row looks like this, shortened. The app asks Laya the same question in the same form:

```json
{"state": {"narration": "UPI/P2M/459863846892/DHAN/Add funds", "direction": "money out of the account",
           "amount": "42425.25", "other_columns": {}},
 "questions": {"category": {"type": "choice", "instructions": "Which spending category does this bank transaction belong to?",
                            "criteria": {"Mutual Fund / SIP": null, "Stocks & Trading": null, "...": null}}},
 "expected": {"category": "Stocks & Trading"}}
```

> **Why category names only, with no descriptions?** Laya fits the question and all its options
> into 192 tokens. With 23 options, each option gets about 7 tokens, so long descriptions are cut
> off and only add noise.

## Step 2 (optional): Check the data on your PC

This step runs Laya's own data check without training. It downloads only the tokenizer, about 2 MB.

```bash
uv run --python 3.12 --no-project --with "laya==0.4.11" --with torch python -c "
from huggingface_hub import snapshot_download
from laya.train import TrainConfig, dry_run
base = snapshot_download('convaiinnovations/laya', allow_patterns=['rl_agent_config.json', 'tokenizer/*', 'encoder/config.json'])
dry_run('training/data/round-1/train.jsonl', base, TrainConfig(eval_data='training/data/round-1/eval.jsonl'))"
```

You should see: `4320 rows read, 4320 valid items, skipped: {}`.

## Step 3: Upload the data to Kaggle

1. Go to **kaggle.com → Datasets → New Dataset**.
2. Upload `train.jsonl` and `eval.jsonl` from `backend/training/data/round-1/`.
3. Name it, for example, `track-my-money-round-1`. Keep it **Private**. Then click **Create**.

## Step 4: Run the training notebook

1. Go to **kaggle.com → Code → New Notebook**, then **File → Import Notebook**, and upload
   `backend/training/kaggle_finetune.ipynb`.
2. In the right panel, under **Session options**:
   - **Accelerator:** *GPU T4 x2*
   - **Internet:** *On*. The notebook needs it to install Laya and download the base model.
3. Click **Add Input** and select your `track-my-money-round-1` dataset.
4. Click **Run All**. Training takes about 30–90 minutes.

The notebook does the following:

| Cell | What happens |
|---|---|
| Settings | Sets the base model, epochs and learning rates. Keep the defaults for round 1. |
| Install | Installs `laya==0.4.11` and checks that a GPU is present |
| Find data | Finds `train.jsonl` and `eval.jsonl` and prints an example |
| Dry run | Checks every row, the same as Step 2 |
| Train | Runs `laya-train`, which **scores the evaluation set before and after** training |
| Package | Zips the checkpoint into `laya-finance.zip` |

**Read the training output.** The before and after evaluation scores tell you how much
fine-tuning helped on the synthetic evaluation set.

## Step 5: Download the checkpoint

1. In the notebook's **Output** panel, download `laya-finance.zip`.
2. Unzip it into the repository so that this file exists:
   `models/laya-finance/rl_agent_config.json`, next to `model.safetensors` and `tokenizer/`.
   The `models/` folder is ignored by git, because checkpoints are large.

## Step 6: Run the model on your PC

From the repository root:

```bash
docker compose --profile laya up -d laya     # first time: builds the image (~5 min)
docker compose ps                            # wait until laya shows "healthy"
cd backend && uv run python scripts/laya_smoke.py
```

The smoke test prints a category for six sample narrations and the speed.

> If the first start stalls during a download, run `docker compose --profile laya restart laya`.
> The download resumes where it stopped. You don't need a Hugging Face key.

## Step 7: Measure it on your own transactions

Synthetic data can make a model look better than it is. Measure it on real data:

1. Upload a few statements in the app.
2. Set the correct category by hand for about **100 transactions**, spread across categories.
   Use the **Category** dropdown. These are saved as `manual`.
3. Load the base model too, then compare:

```bash
LAYA_MODELS=english,laya-finance docker compose --profile laya up -d laya
cd backend && uv run python training/evaluate.py --round 1
```

The script compares three categorisers on the same transactions:

- `laya-english`: base Laya, not fine-tuned
- `laya-finance`: your fine-tuned model
- `tfidf`: a tiny classic model (character n-grams and logistic regression) trained in about a
  second on the same synthetic data. It shows whether fine-tuning a large model is worth it.

**Decision rule:** use `laya-finance` only if it gets **at least 85% on your labelled transactions**
and clearly beats `laya-english`.

## Step 8: Use it in the app

`backend/.env` already contains `LAYA_MODEL=laya-finance`. Restart the backend, then click
**Categorise** on a statement. New uploads are categorised automatically.

## Not good enough yet? Run another round

`evaluate.py` prints the most frequent mistakes, for example `Groceries -> Food & Dining`. Add
data aimed at exactly those categories:

```bash
uv run python training/generate_dataset.py --round 2 --per-category 0 \
    --focus "Groceries,Food & Dining" --extra 400 --mix-previous 0.3
```

This writes `data/round-2/`. It contains 400 new examples for each focus category, plus 30% of
round 1's rows, so the model doesn't forget what it already learned. Then:

1. Upload round 2 as a new Kaggle dataset.
2. Add your round-1 checkpoint as an input too: upload `laya-finance.zip` as a dataset.
3. In the notebook's **Settings** cell:
   ```python
   BASE = "/kaggle/input/<your-checkpoint-dataset>/laya-finance"
   ENCODER_LR = 1e-5
   HEAD_LR = 5e-5
   ```
   The lower learning rates make small adjustments instead of big jumps.
4. Run it, download the result into `models/laya-finance-r2/`, and evaluate it.
5. **Keep it only if accuracy on your real transactions goes up.**

If you changed the data a lot, train from the base model again instead (`BASE = "convaiinnovations/laya"`).

When synthetic rounds stop helping, the next step is to train on **your own corrected
transactions**. Those are personal data, so train on your PC (slow, overnight) instead of Kaggle.

## Troubleshooting

| Problem | Cause | Solution |
|---|---|---|
| `assert torch.cuda.is_available()` fails | No GPU selected | Set **Accelerator** to *GPU T4 x2*. Your account must be phone-verified. |
| `pip install` or the model download fails on Kaggle | Internet is off | Set **Internet** to *On* |
| Laya answers `400 request body must be valid JSON` | The TypeSafe SDK compresses large requests | Already handled: the app sends uncompressed requests to Laya (`compression=False`) |
| Laya stays "starting" for a long time | A weight download stalled | `docker compose --profile laya restart laya` |
| Every answer is the same category | The model used is not the fine-tuned one | Check `LAYA_MODEL=laya-finance` and that `models/laya-finance/` exists |
